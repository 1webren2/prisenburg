# script_review · 第一幕人工编辑稿

## 这是什么

这是**当前实际剧本**的一份完整导出，供人工重写第一幕用。

- **它不是游戏的一部分。** 这里的所有文件都不参与运行：不改 loader、不进 `composeStories`、
  不改 `act1/`、`act2/`、`act3/`、`daily/`、`hunt/` 里任何剧情文件的读取逻辑。
- **它是从 JSON 机械导出的**，没有润色、没有改写、没有补写、没有纠正。
  导出脚本按 `next` / `continueTo` / `choices[].next` 把「选项 → 反应 → 后续对白 / 结果」
  一路展开，凡是有分支的地方都写到了；没有一处是概述。
- 导出用的是一次性脚本，跑完已删除。改完 Markdown **不要**指望它回灌 —— 回填是人工的。

## 编辑规则

1. **不要删节点 ID。** 每个小节都带着原始 ID（`` `b12_morning` `` 这种）。它是回填时唯一的定位手段。
2. **正文直接改。** 台词、旁白、场景描述，改在 `#### 场景正文` 那一段里就行。
3. **增删选项时保持 A / B / C 结构。** 一个选项块 = `**A：文案**` + 下面几行 `- 选择后的反应 / - 后续对白 / - 结果 / - 数值效果 / - 日记记录`。
   删一个选项就连它那几行一起删；加一个就照着复制一份。
4. **数值效果、`next`、`if` 只作参考。** 它们是从数据里读出来的，不是修改建议 —— 不要照着它们直接去改游戏文件。
5. **改完不要动原游戏文件。** 回填是另一步的事。
6. 需要在正文里说明什么，直接写在 `>` 引用块里，或者在段末加一行 `<!-- 批注：…… -->`。

## 怎么读这些文件

- `00_第一幕流程总表.md`：**只有索引**，没有正文。想知道「哪天有哪些活动、入口节点是什么」，看它。
- `01` ~ `12`：正文。原著主线按**节点顺序**逐节点导出，没有被合并成概述；
  日常层按「时段菜单 → 每个方向一个活动」导出。
- `13_幕间自由活动.md`：两处自由活动入口、四个房间、换装、来访、报仇与全剧终。
  这一层是侧厅，不接主线；里面的台词目前全是 `[...]` 占位文本。

## 三个层次，别混起来

| 层 | 在哪 | 谁写的 | 原文核对 |
|---|---|---|---|
| **原著主线** | `act1/`、`act2/`、`act3/`（+ 狩猎篇 `hunt/ch4~ch8.json`） | 小说原文逐字重建 | **查**（`tests/fidelity.cjs` 正查 + 反查） |
| **日常层** | `daily/story.json` | 新写的 | 不查（`daily/` 故意不进 `fidelity.cjs`） |
| **幕间自由活动** | `act2/story.json` 的 `freeRoam` 块 | 占位 `[...]`，等作者替换 | 不查（刻意放在节点 `dialogues` 外面） |

> **红线**：原著主线的台词只能用小说原文逐字重建，不能自编。
> 自编文本一律不进节点的 `dialogues` —— 日常层的日记正文放在 `daily.diary` 块里，
> 自由活动的占位文本放在 `freeRoam` 块里，都是这个道理。

## 日记是怎么长出来的

- 日记是**西比拉视角**：写的是「她选择让你看到的内容」，不是系统显示的数值。
  玩家看不到「埋怨 +5」，只看到她写下的那一句话。
- 日记能**补完没有亲历的原著段**：玩家把某个时段花在别处时，原著照常发生
  （数值沿默认走法落，见 `act1/engine.js` 的 `applySegmentDefaults`），只是没有亲历，
  事后由她自己在日记里记一笔。
- 日记里允许有一点**玩家痕迹**：玩家做的事是她那天「有什么可以写」的**原因**，不是那句话的主语。
  ——不写「奥布里取消了我的课程」，写「上午没有为伊莎贝尔小姐授课」。

### 一页日记由两半组成

| 半边 | 在哪 | 谁决定 |
|---|---|---|
| **今日事件**（她今天做了哪几条） | 各选项的 `choice.diary` 字段 | 玩家走过的路（对照那几个「记录旗」） |
| **她写下的那一页**（分档语气） | `daily/story.json` 的 `daily.entries[].body` / `.tiers` | 当天算出来的档位 |

### 四档语气（`daily/diary.js` 的 `tierOf()`）

| 档 | 条件 |
|---|---|
| 4 | `西比拉_好感 >= 60` 且 `西比拉_亲密 >= 45` 且 `西比拉_恨意 < 30` |
| 3 | （`西比拉_好感 >= 40` 且 `西比拉_亲密 >= 25`）或 `西比拉_埋怨 >= 30` |
| 2 | `西比拉_好感 >= 20` 或 `西比拉_亲密 >= 10` |
| 1 | 其余 |

数据里 `body` 就是档 1，`tiers[2..4]` 只写高出档 1 的那几档。缺哪一档就往低处回落。
**第 1 天只有 `body`** —— 那天她刚领到册子，还谈不上语气。
日记正文**不写数值、不写属性名**：玩家读到的是一整页人写的话，不是一行日志。

### 每一天的日记在哪

见 `00_第一幕流程总表.md` 末尾的「日记总表」。
每个 `01`~`07` 文件的末尾都有一个 `### 当日日记 · 第 N 日` 小节，里面是：
`#### 可见记录`（哪几个选项可能被写进去、取数用的是哪面旗）、
`#### 她写下的那一页（按档）`（四档全文）、
`#### 未亲历主线补完`（没亲历的原著段，她补记的那一段正文）。

日记正文**不是节点台词** —— 它从来不在 `dialogues` 里，所以原文核对照不到它。
