# 游戏实际运行稿

**这个文件夹里没有一行代码在跑。** 游戏真正跑的是各幕目录下的 `story.json`，
它们必须留在原地（引擎按相对路径加载、`tests/` 里写死了路径、`server.js` 拿它校验存档），
所以这里放的是**可以随便改的文稿副本与作者稿**，以及一份「运行稿在哪」的索引。

---

## 一、真正在跑的文稿（原地不动）

| 文件 | 是什么 | 节点数 |
|---|---|---|
| `act1/story.json` | 第一幕（序章 · 西比拉视角） | 34 |
| `act2/story.json` | 第二幕（奥布里视角）+ 幕间自由活动的 `freeRoam` 块 | 42 |
| `act3/story.json` | 第三幕 | 33 |
| `hunt/ch4.json` ~ `hunt/ch8.json` | 狩猎篇第四～八章 | — |
| `hunt/ch9.json` | 第九章（脱链留档，见 `tests/server.test.cjs`） | — |
| `daily/story.json` | 日常层（第二天起的时间线、熬药、账册） | 119 |
| `stage0/story.json` | Stage 0 日记本原型（实验，挂在 `act1/` 旁边） | — |

**改完之后必跑：**

```bash
node tests/run.cjs          # 六道逻辑测试（engine / ui / server / fidelity / daily / brew）
node act1/game.js --validate # 剧本自检：节点、结局、可达性
node tests/shots.cjs        # 无头截图 + 量真实尺寸（--e2e 是从开始界面真玩一遍）
```

**红线：原著主线的台词只能用小说原文逐字重建，一个字都不能自编。**
`tests/fidelity.cjs` 有正查（不许自编）+ 反查（不许漏掉）两道机械核对。
唯一的例外是自由活动里用户明确允许的 `[...]` 占位文本 —— 它们放在 `freeRoam` 数据块里，
**不许进节点自己的 `dialogues`**，进了就会被原文核对拦下。

## 二、这个文件夹里有什么

### `script_review/` —— 当前实际剧本的人工编辑导出（14 份 + README）

从 JSON 机械导出的通读稿，供人工重写第一幕用。**它自己写明不参与运行**
（不改 loader、不进 `composeStories`）。导出脚本是一次性的，跑完已删 ——
**改完 Markdown 不要指望回灌，回填是人工的。** 编辑规则见 `script_review/README.md`。

- `00_第一幕流程总表.md` 只有索引；`01`~`12` 是正文；`13` 是幕间自由活动侧厅。
- ⚠️ **它是首轮回填前的快照（10-02 / 10-06 生成）**，里面的日常层节点名（如 `dy_d2_mo_hl_e`）
  已随第二轮改名。没有自动重生成 —— 要重生成的话得先把导出脚本重写一遍。

### `普里森堡_剧情稿整理与Claude首轮修改资料包/` —— 作者交的首轮资料包

> 原名 `_instr_round1/`。搬进来时**剥掉了 `02_原著参考/`** —— 那 4 份原著 txt
> 与 `store/` 逐字节相同（纯重复副本），已挪到 `游戏小说原稿/原著参考_第六至九章/`；
> 里面那份 `script_review_README.md` 与 `script_review/README.md` 也完全相同，挪进了 `废件/重复文件/`。
> 所以包里的 `文件清单.md`、`README_资料包索引.md` 提到 `02_原著参考/` 的地方已经不对了。

- `01_当前剧情稿/`（14 份）：作者按节点 ID 展开的人工编辑稿、玩法调整稿、狩猎篇对白旁白版、
  第五天狩猎取消线的作者原文只读稿（`第五天_狩猎取消线_作者原文只读.md`）、幕间自由活动参考。
  **首轮回填的正文就是从这一批稿子来的。**
- `03_首轮执行指令/Claude_Code_首轮剧情回填指令.md`：交给 Claude Code 的可执行任务指令。
- `剧情稿汇总总稿_阅读版.md`：把上面各稿自动拼成一份连续阅读副本（50 万字节），
  **不用作回填的唯一依据**，要改请回对应独立文件。
- `文件清单.md` / `README_资料包索引.md`：资料包的用途清单与索引。

**冲突处理优先级**（资料包 `01_当前剧情稿/00_总览与分支规则.md` 里写的，照抄）：

1. 作者在对话中明确确认的规则与作者亲自写出的正文（尤其《第五天_狩猎取消线_作者原文只读.md》）。
2. 《第三至第六天_正式剧情稿_v2_人物性格与日程校正版.md》里的时间线、人物排程、分支和 POV 规则；
   与作者随后追加的专属分支正文冲突时，以作者明确补充为准。
3. 各日「人工编辑稿」里的节点 ID、原有节点全文、选项、旗标和定位信息，用于映射运行文件。
4. 《第二天_玩法调整稿_v2》作第二天选择/状态设计依据；《第二天_执行顺序明确版人工编辑稿》作节点映射依据。

### `普里森堡_第一二天剧情稿_第一夜日记后续衔接修正版.docx`

作者最新交的稿。**第二天早晨的教室线**（`daily/story.json` 里 `dy_d2_mo_cls_door_e` ~ `_after_e`
七节）正文逐字取自它，基准抄成了纯文本放在 `store/第二天早晨教室线.txt`，
由 `tests/daily.test.cjs` 按拼接逐字钉住。稿子里「后续：…」那几行是**给制作方的注记，不是台词** ——
它们存在三个选项的 `_note` 里。

### `回填报告_首轮.md`

首轮回填的完整记录：改了什么、哪些没动、留了哪些尾巴。**想知道「某个节点当初为什么这么写」先翻它。**

## 三、改剧情该动哪儿

| 想改什么 | 动这个文件 | 改完跑 |
|---|---|---|
| 第一 / 二 / 三幕台词、选项、数值 | `act1/` `act2/` `act3/` 的 `story.json` | `node tests/run.cjs fidelity` + `--validate` |
| 日常层（第二天起的时间线、活动） | `daily/story.json` | `node tests/run.cjs daily` |
| 狩猎篇 | `hunt/chN.json` | `node tests/run.cjs fidelity daily` |
| 熬药的药材 / 药方 / 账目 | `daily/alchemy.js`、`daily/story.json` 的 `pharmacy` 块 | `node tests/run.cjs brew` |
| 幕间自由活动 | `act2/story.json` 的 `freeRoam` 块 | `node tests/run.cjs engine` |

细节规矩（哪些数字一改就红、哪些正文不许碰）全写在仓库根的 **`CLAUDE.md`** 里。
