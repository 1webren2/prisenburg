## 0. 一句话

> 日记本是**西比拉在记录自己的生活**。玩家做的事，只是改变了她今天有什么可以写。

它不是奖励，不是任务清单，也不是系统给你看的结算表。

## 1. 两套状态：`diaryLog` 和 `diaryHistory`

这两个是**不同的东西**，文档里必须分开说。Stage 0 只做前者。

| | `diaryLog` | `diaryHistory` |
|---|---|---|
| 是什么 | **当前这一天的临时状态**：今天记了哪几条 | **长期记录**：第 1 天、第 2 天……每一天各记了什么 |
| 生命周期 | **每天清空**（睡下 → 第二天，重新开始记） | 跨天累积，一直往后加 |
| Stage 0 | **做**（一天，最多 5 条） | **不做** |
| Stage 1 | 升级成 `diaryLog[phase] = []`（一个时段一个真数组） | 实现 —— 有了它才有「翻回前天看看」 |
| 谁来读 | 日记页面（当天那一页） | 日记本翻页、结算屏回看入口 |

**Stage 0 不实现历史翻页。** 只有一天，翻页翻过去还是同一页，
所以界面上连翻页控件都不做（做了也是灰的，是假装）。

这个区分的意义在于：`diaryLog` 是**会变的运行时状态**，`diaryHistory` 是**攒起来的档案**。
v2 把两件事混在一起（一个 `entries` 数组既当今天又当历史），是错的 ——
所以 v3 把它拆开。

## 2. 数据格式

### 2.1 静态那一半：`choice.diary`

**日记的文本挂在选项上。** 选了这个选项，就记下这句话。

```jsonc
{
  "text": "把伊莎贝尔的礼仪课停了。",      // 选项本身（玩家看到的按钮）
  "next": "e_stop_class",
  "diary": "上午没有为伊莎贝尔小姐授课。",   // ← 日记里记的那一句
  "effects": [ { "stat": "旗_今日停课", "value": 1 } ]
}
```

- **Stage 0 的 `choice.diary` 只支持固定字符串。** 不写对象、不写条件。
- Stage 1 若需要「属性驱动的日记语气变化」（比如同一件事，好感高 / 埋怨高
  写成两个调子），再把它升级成**条件式 diary variant**：
  ```jsonc
  "diary": [ { "text": "……", "if": { "stat": "西比拉_埋怨", "op": ">=", "value": 30 } },
             { "text": "……" } ]
  ```
  语义跟 `dialogues[].if` 一样，第一条命中者赢。**Stage 0 不做。**
- 引擎不认识 `diary` 这个键，也不报错（跟 `diary` 数据块、`freeRoam` 一样，
  它是给界面层读的）。

### 2.2 运行时那一半：`diaryLog`

`diaryLog` 是**今天记下来的那几条**，每天清空。

**Stage 0 的实现方式**：因为「**每个时段最多一条记录**」（见 §2.3），
一天最多 4 条，所以 `diaryLog` 落在 **`stats` 的四个数字槽**里，不另开结构。

槽里存的是「有没有这一条」，文本仍然从 §2.1 的 `choice.diary` 取。
判定用 `effects` 里已经在写的那些旗：

```jsonc
"effects": [ { "stat": "旗_今日停课", "value": 1 } ]
```

这样做的唯一理由是**存档**：`snapshot()` 只认 `nodeId + stats + lineIndex`
（CLAUDE.md 明写），只有数字进得去。**换了别的存法，「读完档日记就空了」** ——
一个显性存档读档就空，那就不叫存档了。

> **已拍板（①）：就用上面的数字槽。**
>
> **代价，写清楚在这里** —— Stage 0 的 `diaryLog` **不是字符串数组**，
> 而是 `stats` 里的 **0/1 标记**。UI 层拿到标记之后，**从 `choice.diary`
> （静态剧情数据）里把文本查出来**再画。也就是说：
>
> - 运行时那半边（谁记了）在 `stats` 里，是数字；
> - 静态那半边（记的是什么字）在 `story.json` 里，永不改动；
> - 两边靠**同一个 flag 名**对上（flag 名就是查表的钥匙）。
>
> 这么做的唯一好处是**存档**：数字能进 `snapshot()`，读档之后日记还在。
>
> **Stage 1 的升级路径**：等 Stage 1 要把它变成真正的字符串数组
> （`diaryLog = ["……", "……"]`），**必须同时改 `snapshot()` / `restore()`**
> —— 那一步绕不开 `act1/engine.js`。**到那时候才能碰 `act1/`**，
> 而且要连带处理存档的向后兼容（老存档里只有 0/1 标记，没有文本）。
> Stage 0 不碰，所以这债是**明账**，不是暗雷。

### 2.3 同一时段可以多条 —— 按触发顺序合并（v3.2）

一个时段里玩家可能点了好几个选项（进门前置 → 事件 → 结果），
**可以有几个都带 `diary`**：早晨既有「课照常 / 停课」那一笔，
课上出了插曲时又有那一笔。v3.1 曾经规定「一个时段最多一条」，v3.2 放开了。

几条**不是并排的几个格子，而是按她今天走过的先后拼成一段**：
`collect()` 先按时段排（早晨 → 中午 → 午后 → 夜晚），同一时段里再按引擎
`visited` 的先后排。`visited` 是个 `Set`（迭代顺序 = 进入顺序），而且**存了档**，
所以读档之后顺序不会乱；拿不到它（袖珍剧本、假引擎）就退回剧本里的先后。
一天最多 5 条。

Stage 1 要把这几条升级成真正的字符串数组（`diaryLog[phase] = []`），
**那时候 §2.2 的数字槽也得跟着换。**

### 2.4 `d1_diary` 节点

`d1_diary` **保留**，但身份变了：

- v2：它是**自动弹出的触发点**，链上从它穿过。
- v3：它是「**西比拉实际写下的日记文本来源**」，**脱链**。

三条约束，缺一不可：

1. **`dialogues` 严格只放日记相关台词**，不写旁白框架
   （翻开册子的是日记页面，不是对话框）。`walkthrough.cjs` 有核对盯着长度。
2. **必须保留 `next: "d1_end"`。** 这一条看着多余，其实要紧：
   `validate()` 把「没有 `next`、没有 `choices`」的节点一律算成**结局节点**
   （`engine.js:1603-1607`），`walkthrough.cjs` 又核死了「只有一个结局 `d1_end`」。
   `d1_diary` 一旦丢了 `next`，结局就变成两个，**测试直接红**。
   顺带：留着 `next`，万一以后真把它接回链上，它有地方可去。
3. **它是「脱链但有人指向」** —— 见 §2.5。

### 2.5 兜底选项：怎么让 `d1_diary` 不触发「走不到」的警告

`d1_diary` 脱链之后，`--validate` 会警告「`d1_diary` 没有任何节点指向它，走不到」。
这条警告本身**说的是实话**（它确实走不到），但它不是「忘接了」，是**有意为之**，
所以得处理掉。办法是在 `d1_diary_intro` 上挂一个**永远不亮的兜底选项**：

```jsonc
"d1_diary_intro": {
  "dialogues": [ /* 奥布里交代规矩。见 §7 的写法 */ ],
  "next": "d1_end",
  "choices": [
    {
      "_note": "兜底：唯一作用是让 d1_diary 有节点指向它，好让 --validate 别报「走不到」。any:[] 恒为假 → 永远锁着；而本节点有 next，advance() 里 next 在 choices 之前（engine.js:620-628），所以这个选项根本不会被画出来。两层保险，玩家一辈子看不见它。",
      "text": "（兜底，不展示）",
      "next": "d1_diary",
      "if": { "any": [] },
      "lockedHint": "兜底用，永不亮"
    }
  ]
}
```

为什么这个办法成立 —— 三条都查过了：

| 担心的 | 事实 | 出处 |
|---|---|---|
| 玩家会看见一个灰按钮？ | 不会。有 `next` 的节点先走 `next`，**根本走不到 `choices`** | `engine.js:620-628` |
| 万一被点到？ | 点不了。`{any: []}` → `[].some()` → **恒为假** → 永久锁死 | `engine.js:144` |
| 自检会不会报「既有 next 又有 choices」？ | 不会。`validate()` 只在**两者都没有**时才报卡死 | `engine.js:1559` |
| `if` 里的东西要先在 `statLabels` 里定义吗？ | 这里没引用任何 stat，不用 | `engine.js:1567` |
| 会不会反而多一条警告？ | 不会。`lockedHint` 配了 `if`，正好反过来躲开那条「写了 lockedHint 却没有 if」的警告 | `engine.js:1568` |

**另一条路（加 `ending: true`）走不通，记在这里免得以后有人再试**：
`validate()` 的「走不到」判定**根本不看 `ending`**，只看别的节点的
`next` / `continueTo` / `choices[].next`（`engine.js:1589-1597`）。
给 `d1_diary` 加 `ending: true` **一条警告都消不掉**，
反而给它贴了个假身份（它是文本来源，不是终点）。

## 3. 术语：静态内容和运行时状态

这两个词在这份文档里是**严格区分**的，别混：

| | 静态剧情数据 | 运行时状态 |
|---|---|---|
| 例子 | `choice.diary`、`choice.text`、`diary.entries[].date/weather` | `diaryLog`（落在 `stats` 的旗上）、`stats` 本身 |
| 在哪 | `story.json` | 内存 / 存档 |
| 会变吗 | **只读**。玩家玩一局，剧本文件一个字都不会变 | 会被修改、保存、恢复 |
| 谁写 | 写剧本的人 | 玩家玩出来的 |

**说「写日记」的时候，写的是运行时状态那一边。** 静态数据只提供「可以写什么」和
「写出来长什么样」，它自己永不被修改。

## 4. 触发与入口：第一天是剧情，之后是按钮

**两个入口，按天数分** —— 这是 2026-09-29 改的，推翻了先前「第一天就挂 HUD 按钮」那版。

### 第一天：剧情带出来的

夜晚时段走完，回到自己房间之后：

```
d1_sleep ──▶ d1_diary_intro ──▶ d1_end
```

`d1_diary_intro` 这一场（**只在第一天出现，之后不再重复**）演的是：

1. 奥布里交代西比拉：**从今天起，每天记录府中事务，回来交给他查看。**
2. 西比拉答应下去，退出来。
3. **过了十几分钟**，她带着写好的日记，**敲响了奥布里的房门**。
4. 门开，**日记摊开** —— 玩家看到的就是西比拉第一天的记录。

也就是说，第一天的日记**不是玩家点开的**，是**剧情推到他面前的**：
她被要求写、写完、送来交差。日记本在这里第一次出场，
亮相的方式是「一件正在发生的事」，不是「一个功能」。

**摊开的时机（实现要点）**：`d1_diary_intro` 的**最后一句台词播完之后**才摊开，
不是一进节点就摊开 —— 那样「敲门」那几句会被书盖住，人还没进来书先开了。
关书之后才走这个节点的 `next` 去 `d1_end`。
（v2 的 `closeDiary()` 里已经有「关书后把剩下的台词快进掉」那段循环，
把开口从「进节点」改成「最后一句播完」就行。）

### 第二天起：HUD 上的【日记】按钮

- 从**第二天**起，日记入口变成 HUD 上的**【日记】按钮**，**玩家主动查看**。
- **不再出现「她敲门」的剧情** —— 那是一次性的交代，不是每天的动作。
- 打开的是**当前这一天那一页**；关掉就回到原来的地方，不推进剧情、不消耗时段。

### 为什么这么分

- **时间逻辑通了**：她实实在在过完了一整天，晚上才有东西可写。
  先前的版本要么「先写了一整天再被交代要写」，要么「按钮永远是暗的」。
- **第一天有引入剧情**（敲门），后面是主动查看 —— 两者不冲突。
- **「不自动弹出」这条原则只对第二天以后成立。** 第一天的摊开是剧情的
  一部分，不是弹出窗口：玩家是在看一场戏，不是被一个 UI 拦住。

## 5. HUD 上永远有两样东西

### 5.1 时间显示（左上角，全天显示）

```
第 1 天 · 早晨
```

- **全天显示**，不只在日记里。玩家任何时候都该知道现在是第几天、什么时辰。
- 「第 1 天」里的**天数先用 `x` 占位**，日后接上真正的时间系统再替换。
  （Stage 0 只有一天，所以恒为 1；占位是为了**先把位置和排版占住**。）
- 时段（早晨 / 中午 / 午后 / 夜晚）从**当前所在的 Hub 节点**推出来 ——
  这个映射已经有了，就在 `stage0.js` 的 `MENUS` 里。
  非 Hub 节点（进了教室、在洗衣房）显示**上一个经过的时段**，全天空着会很怪。

### 5.2 【日记】按钮（**第二天起**才有的 HUD 按钮）

- **从第二天起**，HUD 上始终有它。不是「有日记才出现」，也不是「第一天就有」。
- **当天还没有记录时，按钮是暗的**（`disabled`）；**有记录之后亮起来**，可以点。
- 什么算「有记录」：**`diaryLog` 非空** —— 今天至少记下过一条
  （至少有一个带 `diary` 的选项被选过）。可能早到【早晨】第一件事。
- **门槛不挂在任何剧情节点上。** 它挂在「今天有没有记过」这个事实本身。

> ⚠️ **推论：这颗按钮属于 Stage 1，Stage 0 不做。**
> Stage 0 **只有一天**，而第一天的入口是剧情（§4：她敲门），按钮要到**第二天**才登场 ——
> 所以**在 Stage 0 里这颗按钮一次都不会亮**。按项目那条「不预实现任何后续系统」
> 的规矩，Stage 0 只做「她敲门 → 摊开 → 第一天那一页」。
>
> **但别搞混 —— 按钮推到 Stage 1，不等于内容也推走。**
> 按 §11 的甲案，`choice.diary` / `diaryLog` / 那四个时段的 0/1 旗
> **Stage 0 照做**：第一天的「今日事件」那几条就是它们算出来的，
> 只是第一天由剧情替玩家把书翻开，玩家不用点按钮而已。
>
> 按钮的**位置、亮暗规则、`diaryLog` 存法**（① 的结论）都写在这份文档里了，
> Stage 1 直接照着做，不用重新设计。

> ⚠️ HUD 上本来就排得满（查看数值 / 保存 / 读取 / 重新开始 / 服务器状态 / 快捷键提示）。
> 再加一个按钮，**1280×720 下可能挤**。这是要量的，等阶段性收尾跑 `shots.cjs` 时看一眼。

## 6. 页面结构：一页式手记

**不要「左页 / 右页」的视觉思维。** 就是一页纸，从上到下一顺读下来：

```
┌─────────────────────────────┐
│  西比拉手记                   │   ← 标题
│                             │
│  第X日 · 阴                   │   ← 日期 / 天气
│  ─────────────────────────  │
│  · 上午没有为伊莎贝尔小姐授课。 │   ← 今日事件（第一人称，见 §7）
│  · 午后洗衣房的活换了人做。     │
│                             │
│  ─────────────────────────  │   ← 分隔线
│  今日：晨起备课，为伊莎贝尔    │   ← 她写的（拼接的日记正文）
│  小姐讲授教义与礼节。……       │
└─────────────────────────────┘
```

自上而下五块：**标题 → 日期/天气 → 今日事件 → 分隔线 → 她写的**。

「她写的」那一块是**拼接**的 —— `d1_diary` 节点里有几条日记台词（Stage 0 是 1 条，
Stage 1 分档之后可能多条），按顺序接起来，中间空一行。

> Stage 0 的这 1 条，就是她的**开场白**：第一次动笔，先交代自己怎么进的府、
> 被安置在哪（§11 甲案）。**它不是玩家长出来的** —— 玩家改的是上面那几条事件。

**视觉**：一本缓缓打开的书（v2 已经做好了，保留）—— `perspective` + 一片绕着
书脊转的封面，纯 CSS，不引库。纸和墨跟 v2 一样。**只是里面不再分左右栏。**

## 7. 叙事原则：她的第一人称，玩家的痕迹

**这是这份文档最重要的一条。**

日记的正文是**西比拉在记录自己的生活**。玩家做的事，只是改变了她今天
**有什么可以写** —— 它不该读起来像「玩家对西比拉做了什么」。

所以日记里**有轻微的「玩家痕迹」**：

| ❌ 不行 | ✅ 可以 |
|---|---|
| 奥布里取消了我的课程 | 上午没有为伊莎贝尔小姐授课 |
| 沃大人让我去院子里练剑 | 上午没有上课。院子里有人练剑，我在窗边看了一会儿 |
| 他打断了我备课 | 蜡版上的字只刻了一半，明天要重来 |

差别在哪：

- **不写「谁对我做了什么」**，写**「我今天是什么样」**。玩家是那件事的原因，
  不是那句话的主语。
- **可以有情绪，但不点破**。「我竟然松了口气」可以，「他太可恶了」不行 ——
  她是受过训练的侍女，不是日记里骂人的孩子。
- **保持账本的骨架，加一点人的温度**。她仍然写「上午 / 午后 / 夜间」，
  但句子开始有轻重了。
- **玩家做的事不能凭空消失**：停课就是停课，不会因为她不想记就不写。
  只是**从她的角度**写。

这条原则在 Stage 1 分档之后会越来越明显：档位越高，句子越离开账本、
越像一个人在跟自己说话。**但「不写谁对我做了什么」这条，四档都不破。**

## 8. 存档

- `diaryLog` 落在 `stats` 的数字槽里（§2.2），所以 `snapshot()` / `restore()`
  **天然就带上了它**，不用加字段。
- 静态那一半（`choice.diary`、日期、天气）本来就在 `story.json` 里，跟着剧本走。
- **合起来的效果**：读档之后翻开日记，看到的就是那一天当时的样子。这就是「显性存档」。

## 9. 与现有系统的交互

- **`--validate` 看不见 `diary` 块和 `choice.diary`**（它只走节点）。所以这两处的
  规矩由 `walkthrough.cjs` 补：
  - `choice.diary` 必须是**字符串**（Stage 0 不支持条件式 variant）；
  - 同一个时段**可以有多个**带 `diary` 的选项 —— 合并时按触发顺序（§2.3）；
  - `d1_diary.dialogues` 长度恒为 1（这条 v2 已经在了）；
  - **`d1_diary_intro` 上那个兜底选项恒锁**：`engine.checkCondition()` 判它是假，
    而且 `availableChoices()` 里它 `enabled === false` ——
    两样都写进走查，哪天有人手滑删了 `next`、兜底按钮冒出来，测试当场拦下。
- **不新增数值属性。** 判定只用已经存在的旗。
- **不引入随机。** 天气写死。存档要可复现。
- **写在文案里的数字不许出现**（跟 `#toast` 那条规矩一样）—— 日记里不许写
  「好感 +5」。

## 11. 已经拍板的两件事

### ① `diaryLog` 落在 `stats` 的数字槽 —— 定了

理由：Stage 0 不改 `act1/`，用数字槽是唯一不碰存档格式的路径。
**代价和 Stage 1 的升级路径写在 §2.2**，一句话：Stage 0 存的是 0/1 标记、
文本现查；升级成字符串数组时必须改 `snapshot()` / `restore()`，**那时才碰 `act1/`**。

### ② `d1_sleep → d1_diary_intro → d1_end`，`d1_diary` 脱链 —— 定了

```
d1_sleep ──▶ d1_diary_intro ──▶ d1_end        ← 玩家真走的路
                  │
                  └─(兜底选项，永不亮)──▶ d1_diary ──▶ d1_end
                                          ↑
                                   只是文本来源，玩家走不到
```

备选（把日记塞进 `d1_diary_intro` 的选项里、让玩家点进去）被否掉，
因为它跟 §4 第一天「她敲门送来」的剧情冲突 —— 那一段要是变成选项，
就成了「要不要看她的日记」，而剧情里她是**已经交上来了**。

**那条「走不到」的 warning 按方案 B 处理**（`d1_diary_intro` 上挂一个
永远不亮的兜底选项），**两个方案里只能选 B** —— 方案 A（给 `d1_diary` 加
`ending: true`）**在引擎里根本不生效**：`validate()` 判「走不到」时压根不看
`ending`（`engine.js:1589-1597`），加了一条警告都不会少，还凭空给它贴个假身份。
详细推演和三条自查见 **§2.5**。

### ③ 第一天的日记怎么记 —— 定了：甲案

起先提过一个说法：「第一天的日记记的是抵达、分房，第二天起才受玩家四时段选择影响」。
**这条跟 Stage 0 的脚本对不上**，查证如下 —— 记在这里，免得以后有人再按那个说法改：

- Stage 0 的「第一天」**就是四个时段那一天**（`d1_wake` → `d1_plan` → 早晨/中午/午后/夜晚）。
- 序章的**抵达、分房在 Stage 0 里根本不存在** —— `meta.description` 明写
  「序章（马车 → 普里森堡 → 大厅初见）不在这里」。
- 现在日记的「今日事件」本来就**是玩家选择算出来的**
  （`旗_今日停课` / `旗_去过洗衣房` / `旗_打断备课` / `决斗_战绩`）。

**采用甲案，两部分各归各位**：

| 那一页的哪一块 | 内容 | 受不受玩家影响 |
|---|---|---|
| **今日事件**（`·` 那几条） | 今天她真正做了什么 | **受** —— 玩家四个时段的选出来的（`choice.diary` → `diaryLog`） |
| **她写的**（分隔线以下） | 她的开场白：**随母亲进普里森堡那天，管事把她安置在哪**，以及她自己的话 | **不受** —— `d1_diary` 节点里的固定台词 |

也就是说，「抵达、被安排房间」**归到她写的正文里**，不进事件列表。
好处是它同时读得通：

- 时间逻辑通了：她实实在在过完了一整天，晚上才有东西可写；
- 「我是怎么到这儿来的」出现在**第一页**，因为那是她第一次动笔，
  一个人写第一页时会先交代自己的来历 —— 之后就不会再提了；
- **Stage 0 仍然验证「显性存档」** —— 事件那几条就是她的存档。

被否掉的**乙案**（整页写死）代价是：四个时段的旗只剩 `d1_end` 在用，
`choice.diary` / `diaryLog` 全落空，**Stage 0 不再验证日记本本来要回答的那个问题**。

## 附录 A · 内容分档（Stage 1）

日记**不每天给反馈**。每天翻开都有新东西、都有数值提示，它就退化成签到奖励了。
多数日子翻开来是平的，偶尔才会扎一下。

| 档 | 名字 | 长什么样 | 条件 |
|---|---|---|---|
| 1 | **事件记录** | 今天做了什么、见了谁。像账本。 | 默认，开局就在这档 |
| 2 | **少量主观观察** | 记录后面多一句她的判断，但还端着 | 好感 ≥ 20 或 亲密 ≥ 10 |
| 3 | **个人情绪** | 写心情、累、委屈、想家。不再是汇报 | 好感 ≥ 40 且 亲密 ≥ 25；**或** 埋怨 ≥ 30 |
| 4 | **真正私密的内容** | 过去、母亲、克莱尔家、她真正在想的事 | 好感 ≥ 60、亲密 ≥ 45，且 恨意 未越线 |

**第 4 档不是「更好」的第 3 档，是另一条路。** 同样够亲密，如果 `恨意` 高，
她写下来的会是另一种私密 —— 那才是危险的那种。

### 同一天、不同档，写出来是两回事

拿「玩家今天把她的课停了」举例：

- **1 档**：`今日：晨起备课，为伊莎贝尔小姐讲授教义与礼节。午后至一楼洗衣房，与女佣同作。夜间备明日之课。`
- **2 档**：`今日礼仪课未能开讲。沃大人另有安排。`
- **3 档 / 好感高**：`课没有上成。他让我在走廊上站了很久，说了些不着边际的话。我不知道他为什么要这样。但今天不用念那本厚书，我竟然松了口气。`
- **3 档 / 埋怨高**：`课又停了。他说了什么我已经忘了，只记得蜡版上刻了一半的那几行，明天还得从头刻起。`
- **4 档**：`……母亲当年也是这样被一件一件拿走的。先是一节课，然后是一整个下午。我应该记着他今天对我笑了。我不该记着别的。`

档位**当天算、当天用，不留历史** —— 玩家把她推远了，日记要跟着冷回去。

> 注意这里 **2 档和 3 档的例句里出现了「沃大人」「他」**，那是分档越高、
> 她越会在自己的日记里写别人。**这跟 §7 的原则不冲突** —— §7 管的是
> **Stage 0 的第 1 档**（纯账本，不写「谁对我做了什么」）。
> 分档本身就是在写「她什么时候开始愿意在日记里提起这个人」。
